# 代码讲解、练习与学习反馈

解释指定片段、通过项目学语言或安排练习时读本分册。以当前源码中的行为为教学单位，讲解长度由用户目标与理解反馈决定。

## 选择讲解深度

| 学习起点 | 优先解释 |
|---|---|
| 语言基础少 | 值、变量、调用、控制流与状态；先给具体输入输出，再解释必要语法 |
| 已会另一门语言 | 熟悉概念在目标语言中的写法差异、惯用方式与运行机制 |
| 已会当前语言 | 模块职责、接口约束、数据所有权、生命周期与有依据的设计取舍 |

基础未知时从一个短片段开始，观察用户是否需要补概念。用户已给学习水平或要求只解释某个点时直接采用，不重新进行长访谈。

## 一段代码讲清哪些内容

从片段在功能链中的用途开始，再按需要覆盖：

1. **写法**：当前语法和符号分别表达什么。解释影响理解的内容，不为每个标点重复翻译。
2. **执行**：一组具体输入下如何求值、调用、返回或更新状态；涉及异步、共享对象和异常时说明顺序与边界。
3. **关联**：谁提供输入、谁使用结果、哪些文件或配置影响行为。
4. **取舍**：与一个合理替代写法比较可读性、复用、可测试性或性能。作者意图有文档才按事实介绍，其余明确为分析。

区分语言语义、框架约定和项目选择。例如 Python 类型提示与运行时校验分别说明；引擎回调、生命周期钩子和普通函数的触发依据分别核实。

当语言写法遮住核心机制时，提供一个简化例子或对照实现，再指出它与真实代码对应的位置、省略的分支和状态。示例的路径、输出和简化逻辑明确标为教学材料；真实源码片段保留必要上下文，省略处明确标注。

## 提问与反馈形成循环

用户要讲解时给完整解释，练习为可选下一步。用户要边学边练时采用以下循环：

1. 带读一个完整的小行为，给必要的语言概念。
2. 让用户预测一个新的输入、解释一条关系、补一个表达式或定位一个消费者。
3. 等实际作答，再比较作答与源码行为。指出误解发生的具体语句或连接，必要时给逐步提示。
4. 用不同的小条件重试；用户能完成后减少提示，扩大到另一个相关功能。

练习题注明起始状态、输入和行为约束，避免靠猜隐藏条件。选择题适合初筛，迁移练习可用边界输入或小改动；有多种正确设计时比较约束和理由，不能只承认预设写法。

练习模式中的待答题与答案分开。先给题目和必要前提，等待用户回答；用户要求提示、解答或一次性教程时按要求提供。静态材料可将解答放在后面的独立位置，并让读者先作答。不要在提出待答题的同一段中直接给出结果。

## 可执行练习的验证

按现有授权选择纸面推演、独立最小样例、已有测试或用户允许的项目运行。区别“按源码推演的结果”与“实际执行的结果”；不能运行时说明范围并提供可复现条件。

练习改动默认放在独立教学位置，尽量少依赖，避免混入工作源码。用户明确要求修改真实项目时遵循项目工作流，保留他人改动。示例执行检查与本轮相关的正常输入和关键边界即可，不扩为整项目认证。

## 完成本轮学习单元

把本轮讲解、用户作答、提示程度和检验依据对应到主技能中的学习证据状态。正确选择一个输出不能直接证明用户能独立写代码；有提示的答案保留提示记录。

针对当前证据推荐下一步。例如调用链已经能解释但对象状态仍混淆，就先用一个状态变化例子补讲；用户要求概览而未练习，则记录已讲解范围和可选练习，不要求先答题才能继续。
