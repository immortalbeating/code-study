# 项目地图与功能追踪

初识项目、找功能入口或梳理模块关联时读本分册。输出围绕当前学习问题，按需要展开；本轮不要求穷尽仓库。

整体学习时先按 [project-view.md](project-view.md) 建立文件与符号索引，再核实真实入口和学习路线。文件树展示源码分布；目录结构不自动等于逻辑架构。完整收录文件原文也不意味着已找到所有运行时关系，分别报告索引范围与分析范围。

## 从运行根找到实际入口

1. 核实项目根、适用指引、README、语言或依赖清单、启动配置。多仓库分别保留身份；结合用户指定的功能确定消费者所在的运行根。
2. 找到程序、页面、命令、场景或服务的真实入口。目录名、文件名和检索排名只是线索；配置、注册位置与调用者提供连接依据。
3. 跟随入口读取当前需要的逻辑模块。根据职责分组，每个模块给出用途、主要入口和关键依赖。层级粒度保持一致，小辅助函数可以归在所属模块内。
4. 阅读量随证据需要增加。先排除无关依赖、生成内容和历史副本；关键函数体、初始化与连接代码必须读到足以支持结论的位置。

例如游戏输入可从动作映射追到处理函数、状态变化和渲染消费者；Web 功能可从路由追到处理器、服务和数据访问；CLI 可从命令注册追到子命令与实际执行函数。采用项目真实的连接方式。

项目地图至少能回答：项目做什么、如何进入、主要职责如何分工、接下来读哪里。源码未确认的模块职责标为候选，不凭文件夹名字补完整架构。

## 用具体场景追一条链

把问题变成可追踪的输入和结果，例如“按下攻击键后，敌人的生命值如何变化”。记录：

- 触发条件与入口符号。
- 依次经过的调用或事件；异步步骤、条件分支和生命周期约束。
- 关键入参、返回值、状态读写及其持有者。
- 最终消费者或可观察结果。
- 影响这条路线的配置、资源、注册表或持久化数据。

仅找到函数定义不能证明它处于本次运行路径。继续查调用者、注册者或消费者；同时识别已断开的、仅测试使用的或历史实现。动态分派、反射、依赖注入、字符串方法名需要额外连接依据。

## 表达关系与证据

| 关系类型 | 需要定位的依据 |
|---|---|
| `import` | 当前模块引用声明及目标定义；只表示代码依赖 |
| `call` | 调用表达式、目标身份、关键入参与返回位置 |
| `event` | 发布者、事件名、连接或订阅位置、接收者；可能有多个目标 |
| `data` | 状态持有者、读写语句、传递对象或返回值 |
| `config` | 配置键、场景资源或路由记录，以及解析它的消费者 |
| `lifecycle` | 初始化、创建、更新、销毁或异步顺序的约束 |

证据状态独立于关系类型：

- `source_confirmed`：源码或配置中已核实该连接；仍不表示相关分支实际执行。
- `runtime_observed`：已在注明的输入、版本和运行条件下观察到这一步。
- `inferred`：依据命名、类型或上下文推断，需要说明推断依据。
- `unresolved`：目标或连接尚无法确定，需要列出缺失信息。

关键连接引用双方符号和连接位置，行号在本次阅读时核实。相同名字的符号使用模块或类型限定，防止把历史实现或另一个语言的同名函数接入链路。

内置生成器只自动分析 Python AST 中的定义、词法导入和部分直接调用；类型提示对应的方法标为 `inferred`，回调表、反射和无法唯一解析的目标保留 `unresolved`。其他语言完整索引 UTF-8 原文，符号与关系由实际阅读、项目配置或可用语义工具补入注解。核实动态注册链时可以添加明确的注解边，保留原自动分析中未确定的调用；注解验证只检查格式、出处和源码版本，不能代替语义核查。

## 组织给学习者的输出

根据任务选择小地图、关系表或时序图。图上的箭头写明“调用”“返回伤害”“读取状态”等动作；调用图和数据流可以分开，控制流应与源码一致。静态连接、观察结果和推断用文字或线型区分，不能仅靠颜色。

随后给出最短可读路线：入口 → 关键逻辑 → 状态或输出消费者。每一站说明为什么读、看哪个符号、带着什么问题进入下一站。跨模块读代码时把必要片段放在同一段导读中，并保留真实源码链接。

结束前核对：关键文件确实存在，入口连接与箭头有出处，未覆盖的分支明确，下一站与本次问题相关。新增目录清单或宏观文档不足以替代对实际功能的追踪。
