# 固定 HTML 项目导读

用户整体学习项目、要求代码关系图或可浏览导读时读本分册。交付一个可直接打开的离线 HTML，三种视图共用一份真实数据：

| 视图 | 交互与学习用途 |
|---|---|
| `atlas` 关系地图，默认首页 | 主干总览、完整文件关系和当前符号；点击节点进入邻域，点击连接或跨层入口联动原文与全部依据 |
| `guided` 路线导学 | 沿真实功能分站阅读，可点击步骤；关键代码、写法解释、预测题和笔记形成理解证据 |
| `reader` 源码精读 | 完整文件、基础代码着色、真实行号、限定符号和关联出处，深入某一段实现 |

固定布局和交互保存在 [study-viewer.html](../assets/study-viewer.html)，项目事实保存在数据和注解中。模板不依赖 CDN、服务器或模型接口。页面是源码快照；打开旧页面本身不会读取当前磁盘或判断代码是否更新。

默认交付可直接打开的 HTML 文件：在资源管理器中双击，用浏览器阅读即可。应用内需要 HTTP 预览时可临时启动本地服务，保留离线文件入口；阅读不需要常驻服务或 Python 进程，Python 只在索引、检查和生成时使用。

## 1. 核实范围并索引源码

确认项目根、运行根和项目指引。默认产物放项目的 `.code-study/`，生成器排除此目录，避免自己的 HTML 和 JSON 再被当成新源码。用户指定别处时采用其位置；若在扫描根内，使用 `--exclude` 明确排除产物目录。

[build_study_view.py](../scripts/build_study_view.py) 仅依赖 Python 标准库，不导入或执行目标项目代码。以下尖括号表示执行时替换的实际绝对路径：

```text
python -X utf8 "<技能目录>/scripts/build_study_view.py" scan --root "<项目根>" --output "<项目根>/.code-study/project-data.json" --title "<项目名称>"
```

默认收录可识别扩展名的 UTF-8 源码、配置和文档；单文件上限 1 MiB，最多 500 个候选文件。文件原文完整保留，不用缩短的片段冒充完整代码。超预算、编码不支持、链接和默认排除项记入 `coverage.excluded`；未读的内容不属于源码覆盖范围。

可重复使用 `--include "src/**" --include "config/**"` 与 `--exclude "archive/**"`，用 `--max-file-bytes`、`--max-files` 按项目大小调整。先看排除清单再决定扩大范围；大型项目可分子系统生成页面，提供总入口说明各自范围，不强塞成一张不可读的大图。

默认跳过依赖、Git、构建目录、`.godot`、Python 缓存及 `.env` 类实际凭据文件；`.env.example` 与 `.env.sample` 可以索引。这是明确文件规则，不是全仓库敏感信息检测；结合项目指引定向排除无关私密材料。链接目录、junction 与文件链接不遍历。

## 2. 阅读并编排教学注解

读取 `project-data.json` 的覆盖统计、文件列表、节点 ID 和关系。自动抽取只支持 Python 定义、词法导入与部分直接调用；其他语言仍保存完整原文，可用语义工具或人工阅读补充符号和关系。入口文件名只提供候选，必须核对启动配置或注册者。

从 [annotations.template.json](../assets/annotations.template.json) 创建注解。具体合同见 [project-data.md](project-data.md)。按实际源码完成：

1. 选择已核实入口，在 `project.entry_node_ids` 写真实节点 ID。
2. 为关键文件或符号写职责、写法解释和设计取舍；不根据目录名虚构架构。
3. 补上配置、事件、数据及动态注册的连接。每条边说明类型、状态、出处与尚缺的条件。
4. 编排至少一条与用户目标一致的路线：入口 → 关键逻辑 → 状态或输出消费者。每站包含阅读目标、关键行、语言写法或机制解释及一个理解题；用户只要讲解时可让 `question` 为空。
5. 将讲解或关系所依赖文件的当前 SHA256 填入 `source_hashes`。相关依据在别的配置文件时也登记它；不是仅为通过校验补齐哈希。

注解覆盖已有节点时只能改 `role` 和 `explanation`。非 Python 新符号须指向真实文件、父节点和行范围。补充边使用自己的唯一 ID，不能覆盖自动边。动态调用即便已有经源码核实的注册链，原自动边仍可保留 `unresolved`；解释两者依据的差别。

解释来自 agent 对实际源码的阅读；生成器不自动写课程。校验通过只证明数据格式、引用和版本一致，不证明讲解语义正确或用户已掌握。

## 3. 构建并核对交互

```text
python -X utf8 "<技能目录>/scripts/build_study_view.py" build --data "<项目根>/.code-study/project-data.json" --annotations "<项目根>/.code-study/annotations.json" --output "<项目根>/.code-study/index.html"
```

可用 `--default-view guided` 或 `--default-view reader` 改首页。`--template` 仅用于维护模板，模板中数据标记 `__CODE_STUDY_DATA__` 必须恰好出现一次。初次整体学习有真实注解和路线后再交付；仅 `scan` 的裸地图可用于中间探索，不声称已完成教学。

构建前会核对当前文件与同范围新增源码；变更或失效注解会拒绝构建。输出采用原子写入，默认保留已有文件；已确认刷新本次派生产物时加 `--force`。输出不能覆盖源码、数据、注解或模板。

打开实际 HTML 核对：选择节点同步原文与关联；切换符号图能看调用者或目标；出处按钮跳到真实文件与行；源码精读保留完整文件；路线显示编排的解释与题目。没有浏览器工具时核对嵌入数据并说明交互尚未验证，不把结构校验当成视觉检查。

文件图按同方向起点、终点聚合边。默认主干在当前筛选中折叠纯辅助关系，明确显示折叠数；“完整关系”及局部邻域打开对应范围的全部文件间连接。模式切换保留筛选，“清除筛选”才重置。一条摘要线包含的类型或状态可能不同，选择后逐条展示原始关系和全部出处，混合依据不能统一标为确认。

相邻层以曲线表达，跨层、同层和回返关系用具名按钮定位两端和证据；小屏采用节点关系列表。完整关系指完整访问当前收录且已记录的关系，不保证全仓库或运行时穷尽。文件内和外部/未知目标仍由当前符号、源码明细与筛选查看。

面包屑可转到完整文件或所属类型；“返回上一处 / 前进下一处”恢复本页的阅读位置、图模式、邻域和选边。导学可以在地图定位当前站点，其序号是阅读顺序。限定名帮助区分同名方法，但符号身份仍使用实际 ID。

向用户提供实际 HTML、必要源码链接和覆盖摘要；桌面宿主可打开生成文件。文件图聚合跨文件关系，同文件内关系在符号视图查看。`external` 或 `unknown` 节点没有本地定义，从调用位置查证，不拿调用者代码当作目标定义。

## 4. 学习、作答与刷新

学习者先在地图找方向，再进入路线。用自己的话复述、预测边界或小改动的结果，保存答案和笔记；将页面的“复制提问上下文”或导出的记录交给 Codex 继续反馈。页面只保存原始证据，不自动评分，不在 HTML 中伪装实时 AI。

续接前执行：

```text
python -X utf8 "<技能目录>/scripts/build_study_view.py" check --data "<项目根>/.code-study/project-data.json"
```

| 输出及退出码 | 后续处理 |
|---|---|
| `current` / `0` | 已登记文件与同扫描范围的可收录路径一致，可以复用这些源码依据 |
| `changed` / `1` | 读取 `changed`、`missing`、`new` 和 `project_root_changed`；重读相关实现、注册与消费者 |
| `unavailable` / `2` | 根、输入或文件读取失败；保留旧产物，明确不能核实的范围 |

若项目移动，可 `check --root "<新根>"` 辅助核对身份；根变化仍需重新索引。刷新顺序是重读相关源码 → `scan --force` → 修订注解 → `build --force`。保留历史学习证据，不仅更新哈希掩盖旧解释。

检查只针对同 include/exclude 规则内的受支持文本，以及已记录的预算排除路径。预算之外的文件内容未读，默认排除目录和未支持的格式不受覆盖保证。代码不变也不证明所有动态目标已知；新增连接与新问题仍需定向追踪。

维护模板的布局、交互或代码着色时，再读 [viewer-design.md](viewer-design.md)；日常项目带读不需要重新设计页面。
