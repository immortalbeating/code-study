# 学习记录与源码续接

用户要求持续带读、保存导读、安排学习路径或续接上次学习时读本分册。一次性短讲解无需创建档案；用户要求只读或不保存时保留本轮聊天上下文即可。

## 确定记录位置

采用用户指定位置或项目已有学习文档约定；否则在项目根的 `.code-study/` 创建本次学习档案，并告知位置。项目已有架构文档作为引用来源，个人学习进度另行记录。

建议按实际需要建立：

```text
.code-study/
├── study-record.md          # 学习目标、证据、待答问题与下一步
├── project-data.json        # 可视导读的完整源码索引与自动关系
├── annotations.json         # 与源码哈希绑定的讲解、补充关系与路线
├── index.html               # 固定模板生成的离线导读
├── lessons/                # 需要反复阅读的导读，短问答可不建
└── source-snapshots/        # 每条需要复用的路线对应源码摘要
```

技能目录保存通用方法，项目档案保存项目事实和个人进度。先读已有文件，再只更新本次学习部分；不自动修改项目指引、忽略规则、历史任务或其他人的学习记录。多用户共用仓库时使用明确的个人记录位置。

初始化可参考 [学习记录模板](../assets/study-record.template.md)。按需要保留字段；所有示例值和待填提示都应替换为本次事实或明确的“未提供”。

## 本轮要留下的内容

- 学习目标、已有基础与用户偏好；缺失项保留未知，避免凭身份推断水平。
- 项目根、运行根、正在读的路线、关键符号和源码范围。
- 每项讲解与关系的依据，包括相应路线的源码快照。
- 用户真实作答、提示程度、验证方式及其来源版本。
- 尚未作答的问题、仍有误解的概念和下一步建议。

学习证据状态使用主技能的定义。课程笔记中的源码事实和用户能力证据分开；旧路线发生变化时，可以保留用户对语言概念的历史理解证据，并把与旧实现相关的结论标为需要更新。

## HTML 中的原始学习记录

按 [project-view.md](project-view.md) 生成的页面，在当前浏览器中保存已浏览位置、明确保存的作答和笔记，并支持导出 `code-study-progress.json`。页面离线运行，没有内置模型；继续提问可复制当前位置、问题和源码哈希回到 Codex。

页面内的返回/前进恢复阅读位置、图模式、邻域及当时筛选，关闭页面后不保留整段导航历史。当前视图、路线站点、图模式及同版源码下的焦点行和选边可恢复；相关源码变化时保留历史作答，重置不能核实的定位信息。

浏览记录不等于理解，作答初始状态只有 `submitted`。导出文件带有项目根和源码哈希；每次作答另存当时的源码范围哈希，保留原答案。刷新页面数据后，旧版本答案显示待核对提示。用户把导出文件用于续接时，先确认项目和当前源码，再给反馈并更新学习档案；不从点击次数或保存动作推断能力。

浏览器存储不可用时可导出本页已保存内容。页面不会自动同步不同浏览器或设备，也不会回写项目文件；不要承诺这些能力。输入框内容需点击保存，未保存内容不属于档案。

## 源码摘要脚本

对本轮实际读取、支撑关键结论的文件使用 [source_snapshot.py](../scripts/source_snapshot.py)。它只读取显式列出的项目内文件，计算 SHA256 和大小，不建立全量索引。只依赖 Python 标准库；Git 可选。

以下路径以真实项目为例。执行时把脚本路径和文件清单替换为当前位置；可从已核实的项目根使用相对路径：

```text
python "<技能目录>/scripts/source_snapshot.py" capture --root "<项目根>" --file "src/main.py" --file "src/battle.py" --file "config/actions.json" --output "<学习目录>/source-snapshots/attack-flow.json"
python "<技能目录>/scripts/source_snapshot.py" check --snapshot "<学习目录>/source-snapshots/attack-flow.json"
```

`--file` 可重复，包含真实入口、已读实现、必要的配置与注册文件。涉及不同仓库时分别捕获。跳过真实凭据、无关依赖、生成内容和学习档案自身；无需把文件原文复制到摘要中。

capture 默认保留已有快照；需要更新本轮所有的派生快照时加 `--force`。先同步已重新核实的导读，再更新对应快照；不能只更新摘要就把旧讲解当作当前事实。脚本拒绝用输出覆盖被登记的源码。

| 操作结果 | 处理 |
|---|---|
| capture 成功，退出码 `0` | 在记录中绑定此快照、路线及本次阅读范围 |
| check 为 `current`，退出码 `0` | 登记文件内容一致，可复用这些文件支持的笔记；仍核对项目身份与本轮范围 |
| check 为 `changed`，退出码 `1` | 文件变更、删除或根位置改变；针对受影响的连接与讲解重新阅读 |
| check 为 `unavailable`，退出码 `2` | 输入不合规、根无效或读取失败；保留旧资料，说明本轮无法核实的范围 |

check 返回 `unchanged`、`changed`、`missing`、`unreadable` 清单，并报告 `project_root_changed`、`git_head_changed`。仅 Git HEAD 改变而登记文件内容一致时，状态仍可为 `current`；不要因此刷新所有课程。项目移动或用户指定新根时，先核实它确实是对应项目，再修正档案身份。

## 续接与局部刷新

1. 核对项目身份、运行根、用户当前目标与待答问题。另一个项目不能沿用这份项目地图；用户明确给出的学习基础可复用。
2. 对本轮将复用的路线执行 check，或在无 Python 的环境中直接重读相关源码并注明摘要检查未执行。
3. 先读变更或缺失文件，再定向检查它们的调用者、事件连接与消费者。更新受影响的关系和讲解，不用重建无关部分。
4. 新增功能、注册记录、配置键或学习范围变化时补查相关文件，再扩充摘要范围。现有快照只覆盖登记文件，不能证明仓库没有新增连接。
5. 结合用户上次作答与本次源码，先回答待答问题或继续最合适的学习单元。记录新证据并给出下一步。

可视导读续接时，对 `project-data.json` 执行生成器的 `check`。同一扫描范围中新出现、删除或变更的源码都需核对；预算排除路径增减或重新可读也会提示刷新。先重新索引，审阅受影响的注解，再构建新 HTML，不能只替换注解里的哈希。浏览器中的旧答案保留历史；具体命令和范围边界见 [project-view.md](project-view.md)。

如果源码身份、关键连接或验证环境无法确认，交付已核实部分并保留缺口；学习进度不因工具失败而被清空，也不因此升级。
